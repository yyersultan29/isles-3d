# Isles 3D — архитектура

Как устроена игра, простыми словами. Правила игры описаны в `GAME_DESIGN.md`, внешний вид — в `DESIGN_SYSTEM.md`,
план работ — в `ROADMAP.md`. Если этот файл расходится с кодом, верен код.

---

## 1. Общая схема

```
 Браузер (GitHub Pages)                                Сервер (Render, Node)
┌──────────────────────────────────┐                 ┌────────────────────────────┐
│ ui/      HUD, меню, диалоги (DOM) │                 │ server.ts  HTTP + WebSocket │
│ scene/   3D-остров (Three / R3F)  │                 │ room.ts    одна комната     │
│    ▲ читают                       │   WebSocket     │    │                        │
│ store/   GameStore ───────────────┼──── JSON ──────▶│    ▼                        │
│    │ локально             онлайн  │◀────────────────┼ game/  тот же движок        │
│    ▼                              │                 └────────────────────────────┘
│ game/    движок правил            │
└──────────────────────────────────┘
```

Главная мысль: **движок `src/game/` один на всех.** В локальной игре он работает прямо в браузере,
в онлайн-игре — на сервере. Интерфейс в обоих случаях получает данные одинаково, через store.

## 2. Движок — `src/game/`

Чистый TypeScript: без React, Three.js и сети. Его можно запускать в браузере, в Node и в тестах.

| Функция | Что делает |
|---|---|
| `createGame({ seed, ... })` | создаёт новую партию: доску, колоду, игроков |
| `validate(state, player, action)` | проверяет, можно ли сделать ход, ничего не меняя |
| `apply(state, player, action)` | возвращает **новое** состояние и список событий, старое не трогает |
| `legalActions(state, player)` | список ходов, которые игрок может сделать прямо сейчас |
| `viewFor(state, viewer)` | состояние, которое видит конкретный игрок: чужие карты скрыты, колода и RNG вырезаны |
| `eventsFor(events, viewer)` | события с теми же скрытыми данными |
| `botAction(state, player)` | ход бота, всегда из `legalActions` |

- **Детерминизм.** Случайность берётся только из сида, текущее состояние генератора лежит в `state.rngState`.
  Одинаковые сид и ходы всегда дают одинаковую партию.
  `replay.ts` переигрывает файл ходов и сверяет хеш (`hashState`): так работают автосейв и тесты.
- **Структура:** `rules/` — правила по темам (постройка, торговля, разбойник, карты, победа),
  `board.ts` — генерация доски, `topology.ts` — гексы, вершины и рёбра, `types.ts` — все типы.
- Ошибочный ход не роняет игру: движок возвращает `EngineError` с кодом (`errors.ts`).

## 3. Store — `src/store/`

Store — посредник между движком и экраном.

- **`gameStore.ts` — локальная игра** (за одним устройством и против ботов). Сам вызывает `apply`, хранит состояние,
  оповещает подписчиков. Автосейв (`autosave.ts`) пишет в `localStorage` файл ходов, а не всё состояние.
- **`onlineStore.ts` — онлайн.** Тот же интерфейс `GameStore`, но ход не применяется локально: он уходит на
  сервер, а store ждёт ответ `update`. Если номер `seq` пропущен, store запрашивает полный снимок.
  Сам переподключается после обрыва.
- **`GameProvider.tsx`** отдаёт store в React. Компоненты читают данные через `useGame(selector)`
  (`useSyncExternalStore`), поэтому перерисовывается только то, что изменилось.
- Анимации (кубики, «+2» на картах, производство) запускаются по **событиям** из `apply`, а не по разнице
  состояний.
- `placement.ts`, `ui.ts` — состояние интерфейса (что сейчас ставим, что открыто). В движок оно не попадает.

## 4. Экран

### 4.1 3D — `src/scene/`
- `World.tsx` собирает сцену: камера, свет, остров, океан, фишки.
- `Island` / `Terrain` / `terrainGeometry.ts` — рельеф клеток. Меши строятся в Web Worker
  (`terrain.worker.ts`), чтобы первая загрузка не подвисала.
- `Vegetation`, `Scenery`, `Ships`, `Harbors`, `Smoke`, `MountainGuy` — декорации. Повторяющиеся объекты
  рисуются через инстансинг и `StaticBatch`.
- `Pieces.tsx` — поселения, города, дороги, жетоны и разбойник. `Placement.tsx` / `TileHover.tsx` — клики по доске.
- `quality.ts` / `frameBudget.ts` — уровни графики и ограничение FPS, чтобы ноутбук не шумел.
- Анимации идут через `useFrame` и ref, без React state на каждом кадре.

### 4.2 HUD — `src/ui/`
Обычный React и DOM поверх канваса: `HUD.tsx` (десктоп), `CompactHUD.tsx` (мобильный), `Lobby.tsx`,
`TradeDialog.tsx`, `DevDialog.tsx`, `TurnClock.tsx`, `Emotes.tsx`, карты в `cards/`.
Переводы лежат в `i18n.ts` и `words.ts`.

## 5. Сервер — `src/server/`

### 5.1 `server.ts` — транспорт
- `POST /rooms` создаёт комнату и возвращает `roomId`. `GET /health` проверяет, что сервер жив (это использует Render).
- WebSocket — у каждого сокета свой `connId`. Сервер только передаёт сообщения: принимает кадр, передаёт его
  в `room.receive()` и рассылает ответы.
- Каждые **250 мс** вызывает `room.tick()` у всех комнат: так идут таймеры.
- Каждые **15 с** шлёт heartbeat (ping): сокет, который не ответил, закрывается.
- Защита (`limits.ts`):
  - ограничения частоты: сообщения, создание комнат, подключения;
  - не больше 500 комнат и 24 подключений на комнату;
  - сообщение не больше 8 КБ;
  - список разрешённых Origin.

### 5.2 `room.ts` — одна комната
Комната не знает про сокеты: `receive(conn, raw)` и `tick()` возвращают список исходящих сообщений
(`Outbound[]`). Поэтому её легко тестировать без сети.

Как идёт игра:
1. `join`: клиент получает `welcome`, а также свой **токен места**, если место свободно. По токену место
   можно вернуть после перезагрузки или с другой вкладки.
2. Хост выбирает таймер и доску (`settings`), затем жмёт `start`.
3. Каждый ход — `action` с `clientSeq`. Если пришёл повтор того же номера, он не применяется второй раз.
   Сервер проверяет ход движком.
4. Если ход прошёл, каждому участнику уходит `update` со **своим** `viewFor`. Если нет — `rejected`.
5. Таймеры (`timeouts.ts`):
   - бросок — 10 с, потом автобросок;
   - ход — 60 с, потом автоматический конец хода;
   - за каждую сделку +15 с, но не больше 180 с;
   - пресеты: relaxed ×2, normal ×1, fast ×0.5, off.
6. **absent**: два таймаута подряд или больше 60 с без связи. Тогда сервер сразу ходит за этого игрока
   значениями по умолчанию, пока игрок не вернётся.
7. Если никто не играет 5 минут, комната закрывается (`ABANDONED`). Пустая комната удаляется через 10 минут.

Протокол целиком описан в `src/net/protocol.ts` (`ClientMessage`, `ServerMessage`). Входящие сообщения проверяет
`parseClientMessage`, а сам ход — движок.

## 6. Сеть на клиенте — `src/net/`
- `connect.ts`: адрес сервера (`VITE_GAME_SERVER` или `?server=`) и создание комнаты. Пока бесплатный сервер
  просыпается (около минуты), показывается ожидание. Здесь же собирается ссылка-приглашение.
- `protocol.ts` — общий файл типов для клиента и сервера.

## 7. Хранение данных

**Базы данных нет.**

| Что | Где | Что будет при потере |
|---|---|---|
| Онлайн-комнаты | память процесса сервера | рестарт или редеплой Render завершает все партии |
| Локальная партия | `localStorage`, файл ходов | восстанавливается переигрыванием |
| Имена, язык, графика, mute | `localStorage` | откатываются к значениям по умолчанию |

Если понадобится БД (рейтинг, история, комнаты, которые переживают рестарт), то план такой: Node + Postgres.
Писать нужно файл ходов (сид + действия), а не всё состояние, потому что движок детерминирован.

## 8. Деплой

| Часть | Куда | Как |
|---|---|---|
| Клиент | GitHub Pages | `npm run deploy` (`scripts/deploy.sh`) собирает сайт и force-push'ит его в ветку `gh-pages` |
| Сервер | Render Free, Frankfurt | `render.yaml`: `scripts/build-server.sh` собирает `server-dist/main.mjs` (только ws + движок) |

- Render пересобирает сервер **только** при изменениях в `src/server/`, `src/net/`, `src/game/` и package-файлах.
  Каждый редеплой обрывает текущие комнаты.
- Бесплатный сервер засыпает после 15 минут простоя. Пока страница открыта, клиент шлёт `ping`, чтобы сервер не уснул.

## 10. Почему так

- **Движок отдельно от экрана**: правила тестируются без браузера, и сервер использует тот же код.
- **Сервер главный**: клиенту нельзя доверять, поэтому каждый ход проверяется на сервере, а чужие карты
  клиенту не отправляются.
- **Комната без сокетов**: её логику можно проверять в тестах без сети.
- **Node, а не Go или Rust**: движок на TypeScript работает и в браузере, и на сервере. Переписывание
  означало бы два движка, которые придётся синхронизировать.
